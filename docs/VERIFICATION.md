# 검증·수정 기록 (작성자 PC 한 대 기준)

이 문서의 모든 결과는 **작성자 PC 한 대**에서 얻은 것입니다. 다른 PC·다른 버전에서의 동작은 확인하지 않았습니다.

## 확인 환경
- Windows 11, Python 3.14.0, 노트북 내장 웹캠
- mediapipe 1.2.2, opencv-contrib-python 5.0.0.93, numpy 2.5.4, pillow 13.0.0, uiautomation 2.0.29
- Edge 156.0.4314.58, Firefox 159.0.1, Chrome 156.0.8078.80, Edge로 설치한 유튜브 앱 (2026-11-07)

"자동 확인" = 테스트 코드 또는 스크립트로 확인, "사용자 확인" = 작성자가 웹캠·손 제스처로 직접 확인

---

## 1. 터미널 버전 (run.py)
- 자동 확인: 패키지 설치, 모델 로드(한글 경로 포함), 웹캠 640×480 약 19 FPS, 손 인식 약 18ms/프레임, 전체 흐름(테스트 모드)
- 발견·수정: 미리보기를 반전한 영상을 MediaPipe에 넣어 Left/Right가 뒤바뀜 → 원본을 넣고 좌표만 거울 기준으로 변환
  (MediaPipe 1.x `HandLandmarkerResult` 설명: 반전된 영상을 넣으면 handedness가 뒤집힘)
- 발견·수정: 창만 활성화하면 `↑/↓` 가 페이지 스크롤이 됨(플레이어 포커스 필요) → UI Automation으로 플레이어 포커스를 확보·확인한 뒤 키 전송
- 사용자 확인 (Edge 브라우저 + Edge 유튜브 앱): 다른 창이 앞일 때 자동 활성화, 검색창 커서 상태, 볼륨이 스크롤 대신 영상 볼륨 변경,
  재생/정지 중복 없음, 인식 종료 후 제어 안 됨, 선택한 대상만 제어, 대상 창 닫힘 시 다른 창에 입력 없음

## 2. 데스크톱 프로그램 (app_gui.py, run_gui.bat)
- 발견·수정: `run_gui.bat` 이 UTF-8/LF로 저장돼 cmd가 줄을 잘못 읽음 → 영문(ASCII)·CRLF로 다시 작성
- 발견·수정: 앱 → 브라우저로 대상 변경 후 첫 명령만 되고 이후 실패. 로그상 모두 `대상 확인` 단계 실패.
  탭 이름이 `- YouTube` 로 **끝나야만** 유튜브로 인정하던 규칙이 재생 시작 후 붙는 표시 때문에 실패 → 이름 안의 ` - YouTube` 위치로 판별.
  같은 원인으로 재생 중인 탭이 목록에서 빠지던 문제도 해결
- 추가: 실패 단계·이유 표시, `실행됨 · 결과 확인 못 함` 구분(재전송 없음), 대상 변경 시 이전 대상 정보 폐기
- 사용자 확인 (Edge 브라우저 + Edge 유튜브 앱): 앱↔브라우저 대상 변경 후 연속 제어, 재생 상태가 섞인 목록, 이전 대상 무반응

## 3. 자동 선택·자동 검색, 다른 브라우저
- 발견: Edge 외 브라우저의 유튜브가 목록에 없음. 원인은 창 종류·실행 파일·주소창 클래스를 Edge(Chromium) 기준으로만 검사한 것
- 수정: 브라우저별 처리(`youtube_target.py` 의 `PROFILES`)와 공통 처리 분리, 화면에 보이는 문서만 사용, 3초 자동 검색, 대상 1개 자동 선택,
  기존 선택 유지, 대상 닫힘 시 대기 명령 취소

| | Edge | Firefox 159 | Chrome 156 |
|---|---|---|---|
| 창 종류 | `Chrome_WidgetWin_1` | `MozillaWindowClass` | `Chrome_WidgetWin_1` |
| 주소창 | 클래스 `OmniboxViewViews` | AutomationId `urlbar-input` | 클래스 `OmniboxViewViews` |
| 탭 | 클래스 `EdgeTab` | 클래스 `tabbrowser-tab` (사이드바 버튼과 구분) | 클래스 `Tab` |
| 웹 문서 | 주소 읽기 가능 | 숨은 `about:newtab` 문서도 보임 → 보이는 문서만 사용 | 처음에는 웹 내용이 노출되지 않음 (4절) |

- 자동 확인: Firefox·Edge 각각 다른 창이 앞일 때 활성화 → 볼륨, 검색창 포커스 상태에서 플레이어 포커스 확보 → 10초 이동,
  한쪽 제어 중 다른 쪽 볼륨 불변

## 4. Chrome
- 처음 상태: 탭·주소창은 읽히지만 웹 내용(문서·주소·플레이어)이 노출되지 않음. UIA 요청·MSAA `WM_GETOBJECT` 요청으로도 5초 안에 변화 없음
  → 이 상태의 Chrome 대상은 `제어 불가` 로 표시, 자동 선택하지 않고, 명령 시 창 활성화 전에 중단하도록 수정
- 확인 과정에서 `chrome://accessibility` 를 열었을 때 `Native accessibility API support`, `Web accessibility`, `Extended properties` 가
  이미 체크된 회색(바꿀 수 없음) 상태였고, 그때부터 웹 내용이 노출됨. **설정은 변경하지 않았음.** 켜진 원인은 확인하지 못함
- 자동 확인: 대상 하나일 때 자동 선택, 다른 창이 앞일 때 활성화 + 뒤쪽 탭 전환, 검색창 포커스 상태에서 10초 이동, 볼륨, 재생/정지
- 사용자 확인: Chrome 완전 종료 후 다시 실행해도 자동 선택·실제 제어 동작 (이때의 `chrome://accessibility` 상태는 기록하지 않음)
